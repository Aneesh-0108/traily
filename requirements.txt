# Phase 1 dependencies.
#
# Only ONE new Python dependency vs Phase 0, explained per AGENTS.md:
#
# - piper-tts==1.8.0 — WHY: the Phase 1 pipeline must synthesize speech
#   locally with the AGENTS.md-selected voice (en_US-lessac-medium), and
#   Piper is that selected engine. WHAT: used only by src/tts/speak.py,
#   which shells out to the `piper` binary (CPU-only: no --cuda flag).
#   WHY IT FITS CPU-only/offline: Piper is a small on-device neural
#   vocoder; it runs on CPU with no network access (model file
#   models/piper/en_US-lessac-medium.onnx is read from disk). It was
#   already installed in the project .venv and is reused, not reinstalled.
#   (Its transitive deps numpy/onnxruntime are pulled in by pip.)
#
# Deliberately NOT added (no Python package needed):
# - whisper.cpp / llama.cpp: used as pre-installed SYSTEM binaries
#   (`whisper-cli`, `llama-cli`) via subprocess, not Python bindings.
#   Python bindings (faster-whisper, llama-cpp-python) would add heavy
#   build/runtime weight for no Phase 1 benefit; the verified CLI flags
#   (-ngl 0 --reasoning off --jinja -st) already give us what we need.
# - Microphone capture: system `parec` (PulseAudio) + stdlib `wave`.
#   No sounddevice/pyaudio: avoids new native deps and keeps the fixed-
#   duration recorder to ~40 lines of stdlib-assisted code.
# - Playback: system `paplay`. No pygame/playsound: same reasoning.
# - Phase 2 OSM/location: Overpass fetch uses stdlib `urllib` + `json`
#   (one POST, one response — no requests lib needed); haversine and
#   pack validation use stdlib `math` + `json`; the GPSD client uses
#   stdlib `socket` on 127.0.0.1 only. No new dependency: the runtime
#   stays offline and the .venv stays minimal.
# - OSM/GPS hardware/web/cloud/fine-tuning: out of scope per AGENTS.md.
#
# Setup may use the network (pip install); RUNTIME is fully offline.
